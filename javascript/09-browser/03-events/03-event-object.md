# The Event Object

## Overview of the Event Interface

When an event occurs in the DOM, the browser generates an **Event object** and passes it as the first argument to any
registered listener callbacks. This object contains all the contextual data about what just happened—such as which
element was clicked, the exact coordinates of the mouse, which keyboard keys were pressed, and the exact timestamp of
the interaction. All specific event types (like `MouseEvent`, `KeyboardEvent`, or `SubmitEvent`) inherit from the base
`Event` interface, meaning they share a core set of standard properties and methods.

## `target` vs. `currentTarget`

The most common source of confusion when working with DOM events is the distinction between `event.target` and
`event.currentTarget`. Because events bubble up the DOM tree, the element that triggered the event isn't always the
element handling it.

| Property                  | Definition                                                                                                                        | Mutability                                                          | Primary Use Case                                               |
|:--------------------------|:----------------------------------------------------------------------------------------------------------------------------------|:--------------------------------------------------------------------|:---------------------------------------------------------------|
| **`event.target`**        | The **originating** element where the event actually occurred (e.g., the specific `<button>` inside a `<form>` that was clicked). | **Static:** Never changes as the event propagates up the DOM.       | Event Delegation (finding out what the user actually clicked). |
| **`event.currentTarget`** | The element to which the **current event listener** is attached.                                                                  | **Dynamic:** Changes as the event bubbles up from parent to parent. | Operating on the container element that bound the listener.    |

```javascript
const list = document.querySelector('ul');

list.addEventListener('click', (event) => {
    // If a user clicks an <li> inside the <ul>:

    console.log(event.target);        // The <li> element that was clicked
    console.log(event.currentTarget); // The <ul> element holding the listener

    // Note: Inside a standard function (not arrow function), `this` equals currentTarget
    console.log(this === event.currentTarget); // true
});
```

## Core Event Properties

Beyond targets, the base `Event` object provides several properties vital for control flow and debugging.

| Property         | Type      | Description                                                                                                            |
|:-----------------|:----------|:-----------------------------------------------------------------------------------------------------------------------|
| **`type`**       | `String`  | The name of the event (e.g., `'click'`, `'keydown'`, `'submit'`).                                                      |
| **`timeStamp`**  | `Number`  | High-resolution timestamp (in milliseconds) of when the event was created, relative to page load.                      |
| **`isTrusted`**  | `Boolean` | `true` if the event was generated by a real user action; `false` if dispatched programmatically via `dispatchEvent()`. |
| **`eventPhase`** | `Number`  | The current phase of propagation: `1` (Capturing), `2` (At Target), or `3` (Bubbling).                                 |

```javascript
document.addEventListener('submit', (event) => {
    if (!event.isTrusted) {
        console.warn('Synthetic form submission detected. Ignoring.');
        return;
    }
    console.log(`Event ${event.type} fired at${event.timeStamp}ms`);
});
```

## Methods for Event Control

The event object also houses the methods required to manipulate the browser's default behaviors and the event's
trajectory through the DOM.

* **`event.preventDefault()`**: Cancels the browser's default action associated with the event (e.g., stopping a form
  from navigating to a new page, or a checkbox from toggling).
* **`event.stopPropagation()`**: Stops the event from continuing to travel through the DOM (halts both capturing and
  bubbling phases).
* **`event.stopImmediatePropagation()`**: Prevents the event from bubbling *and* prevents any other listeners attached
  to the *same* element from executing.

## Subclass-Specific Properties

Because events inherit from the base `Event`, they carry additional data specific to their interaction type.

### Pointer / Mouse Events (`MouseEvent`, `PointerEvent`)

* `clientX` / `clientY`: Coordinates relative to the visible viewport.
* `pageX` / `pageY`: Coordinates relative to the entire document (including scroll).
* `button`: Indicates which mouse button was pressed (`0` = Main/Left, `1` = Auxiliary/Middle, `2` = Secondary/Right).

### Keyboard Events (`KeyboardEvent`)

* `key`: The string value of the character pressed (e.g., `'a'`, `'Enter'`).
* `code`: The physical layout location of the key (e.g., `'KeyA'`, `'Enter'`).
* `ctrlKey`, `shiftKey`, `altKey`, `metaKey`: Boolean flags indicating if modifier keys were held down during the event.

## Best Practices

* **Use `target` for Delegation:** Rely on `event.target` when you want to handle events for multiple child elements
  using a single listener on their parent container.
* **Trust `isTrusted` for Security:** When dealing with sensitive actions (like opening a popup window or processing a
  payment), verify `event.isTrusted === true` to ensure the action wasn't triggered by a malicious script simulating
  clicks.
* **Read Properties Early:** Event objects are technically mutable and recycled in some older framework architectures (
  like React 16 and older). If you need to access event properties asynchronously inside a `setTimeout` or Promise,
  extract the values into primitive variables synchronously first.
