# DOM Elements

## Element Interface and Inheritance

An Element node represents a structural tag within an HTML document structure. In the DOM class hierarchy, the `Element`
interface extends the base `Node` interface, adding specific properties and methods for managing HTML attributes,
styling, layout geometry, and child element selection. Every specific HTML tag—such as a `<div>`, `<button>`, or
`<input>`—is represented by an object that inherits from `Element` through `HTMLElement`. This inheritance hierarchy
ensures that all HTML elements share a core set of DOM manipulation features while maintaining unique capabilities
tailored to their structural purpose.

| Interface Class         | Typical HTML Tags | Key Capabilities                                     |
|:------------------------|:------------------|:-----------------------------------------------------|
| **`HTMLDivElement`**    | `<div>`           | Generic container layout properties                  |
| **`HTMLButtonElement`** | `<button>`        | `disabled`, `type`, `form`, click focus controls     |
| **`HTMLInputElement`**  | `<input>`         | `value`, `checked`, `type`, input validation methods |
| **`HTMLAnchorElement`** | `<a>`             | `href`, `target`, URL decomposition properties       |

## Element Traversal vs Node Traversal

Standard node traversal properties return all adjacent nodes, including text nodes generated by whitespace and line
breaks. Element-only traversal properties ignore non-element nodes (such as text and comments), navigating strictly
between HTML tag elements. Using element-centric traversal avoids accidental processing of empty text nodes and
whitespace fragments when navigating document structures.

| Node Traversal Property | Element Equivalent       | Target Entity                                                         |
|:------------------------|:-------------------------|:----------------------------------------------------------------------|
| **`parentNode`**        | `parentElement`          | Parent element container (returns `null` if parent is not an element) |
| **`childNodes`**        | `children`               | Collection of direct child element nodes (`HTMLCollection`)           |
| **`firstChild`**        | `firstElementChild`      | First child element node                                              |
| **`lastChild`**         | `lastElementChild`       | Terminal child element node                                           |
| **`previousSibling`**   | `previousElementSibling` | Immediately preceding sibling element                                 |
| **`nextSibling`**       | `nextElementSibling`     | Immediately following sibling element                                 |

## Tag Metadata and Namespaces

Element nodes provide properties to inspect tag identification and namespace metadata. These properties allow
applications to evaluate element types, handle XML/SVG namespaces, and process custom elements dynamically. Checking
`namespaceURI` is particularly relevant when working dynamically with embedded SVG or MathML elements alongside standard
HTML elements.

| Property           | Format / Output                   | Description                                                |
|:-------------------|:----------------------------------|:-----------------------------------------------------------|
| **`tagName`**      | Upper-case string (e.g., `'DIV'`) | Returns tag name for HTML elements                         |
| **`localName`**    | Lower-case string (e.g., `'div'`) | Returns local part of qualified element name               |
| **`namespaceURI`** | URL string or `null`              | XML/SVG namespace URI (e.g., `http://www.w3.org/2000/svg`) |
| **`id`**           | String                            | Value of element `id` attribute                            |

## Element Search and Match Verification

Element instances provide utility methods to search their descendant subtree or verify whether they match specific CSS
selector criteria. The `closest()` method is especially useful in event delegation handlers to identify whether an event
target or one of its parents matches a required selector.

| Method                           | Parameters          | Return Value        | Primary Use Case                                   |
|:---------------------------------|:--------------------|:--------------------|:---------------------------------------------------|
| **`matches(selector)`**          | CSS selector string | `boolean`           | Checks if element satisfies selector criteria      |
| **`closest(selector)`**          | CSS selector string | `Element` or `null` | Traverses upward to find nearest matching ancestor |
| **`querySelector(selector)`**    | CSS selector string | `Element` or `null` | Finds first descendant matching selector           |
| **`querySelectorAll(selector)`** | CSS selector string | `NodeList`          | Finds all descendants matching selector            |

## Use Cases

* **Event Delegation Target Matching:** Using `event.target.closest('.btn')` inside a container listener to locate
  clicked buttons regardless of nested icon spans.
* **Component Type Checking:** Inspecting `element.tagName` or using `element.matches()` to apply conditional processing
  logic based on element type.
* **SVG and Namespace Handling:** Creating and manipulating dynamic SVG vector graphics using
  `document.createElementNS()` and checking `namespaceURI`.
* **Clean Subtree Navigation:** Iterating through `element.children` to inspect or reorder DOM components while
  bypassing whitespace text nodes.

## Best Practices

* **Prefer Element Traversal Over Node Traversal:** Use `children`, `firstElementChild`, and `nextElementSibling` to
  prevent layout bugs caused by whitespace and comment nodes.
* **Use `closest()` for Event Delegation:** Handle clicks on nested element targets by resolving the target to its
  expected parent component using `closest()`.
* **Account for Case Sensitivity in `tagName`:** Remember that `tagName` returns uppercase strings in HTML documents, so
  compare against uppercase strings (e.g., `element.tagName === 'BUTTON'`).
* **Leverage `matches()` for Conditional Checks:** Avoid complex `if` conditions with tag names or class lists by
  testing elements directly with `element.matches('.active-item')`.
* **Avoid Modifying Native Element Prototypes:** Do not add custom properties directly to `Element.prototype` to avoid
  namespace collisions with future Web APIs.
* **Validate Element References Before Property Access:** Always verify that `querySelector()` or `closest()` returned a
  non-null element reference before calling methods or accessing properties on it.
