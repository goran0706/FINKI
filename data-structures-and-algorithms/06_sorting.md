## Пребарување (Searching)

Пребарувањето е постапка со која се проверува дали одреден елемент постои во колекција и, доколку постои, се одредува
неговата позиција.

### Колекција на записи

Колекција на записи е збир од записи, при што секој запис содржи повеќе полиња со податоци за одреден објект. Едно од
полињата се избира како **клучно поле (key field)** и се користи за идентификација и пребарување на записите.

На пример, колекција на записи за вработени може да ги содржи следните податоци:

| **ID** | **Име** | **Плата** |
|-------:|---------|----------:|
|    104 | Ана     |     45000 |
|    102 | Марко   |     52000 |
|    108 | Елена   |     48000 |
|    101 | Петар   |     41000 |

Во овој пример, полето `ID` е клучно поле според кое се пребаруваат записите.

Колекцијата на записи може да се чува на два начина:

- **Подредена колекција:** записите се подредени според вредностите на клучното поле, во растечки или опаѓачки редослед.
- **Неподредена колекција:** записите не се подредени според вредностите на клучното поле и може да се појавуваат во
  произволен редослед.

На пример, ако записите се подредени според полето `ID` во растечки редослед, нивните вредности ќе бидат
`101, 102, 104, 108`. Во спротивно, редоследот може да биде произволен, како во претходната табела.

**Избор на алгоритам за пребарување**

Изборот на алгоритам зависи од тоа дали колекцијата е подредена или неподредена:

- **Секвенцијално пребарување (Sequential Search):** се користи за неподредени колекции, бидејќи записите мора да се
  проверуваат еден по еден. Може да се примени и врз подредени колекции, но не ја искористува нивната подреденост.
- **Бинарно пребарување (Binary Search):** се користи исклучиво врз подредени колекции. Со споредување на бараниот клуч
  со клучот на средишниот запис, во секој чекор се отфрла половина од преостанатата колекција.

Кај неподредена колекција, бинарното пребарување не може директно да се примени. Колекцијата најпрво мора да се сортира
според клучното поле, при што треба да се земе предвид и времето потребно за сортирање.

Кај подредена колекција може да се применат двата алгоритма, но бинарното пребарување е поефикасно за големи колекции,
особено кога се извршуваат повеќе пребарувања.

### Секвенцијално пребарување (Sequential Search)

**Основна идеја**

Секвенцијалното пребарување ги проверува елементите еден по еден, почнувајќи од првиот елемент, сè додека не го пронајде
бараниот елемент или не стигне до крајот на колекцијата.

Алгоритмот може да се примени и врз подредени и врз неподредени колекции. Особено е корисен кога колекцијата е
неподредена, бидејќи не бара претходно сортирање.

**Постапка**

1. Се започнува од првиот елемент.
2. Тековниот елемент се споредува со бараниот клуч.
3. Ако се еднакви, се враќа позицијата на пронајдениот елемент.
4. Во спротивно, се продолжува со следниот елемент.
5. Ако се проверат сите елементи без пронаоѓање, се враќа `-1`.

**Псевдокод**

```text
SEQUENTIAL_SEARCH(A, n, key)
    for i = 0 to n - 1
        if A[i] == key
            return i

    return -1
```

**Пример**

Дадена е неподредената низа:

```text
A = [8, 3, 12, 5, 9]
key = 12
```

Проверувањето се одвива последователно:

```text
8  != 12
3  != 12
12 == 12  → пронајден на индекс 2
```

**Java имплементација**

```java
public class SequentialSearch {

    static int search(int[] array, int key) {
        for (int i = 0; i < array.length; i++) {
            if (array[i] == key) {
                return i;
            }
        }

        return -1;
    }

    static void main(String[] args) {
        int[] array = {8, 3, 12, 5, 9};

        int index = search(array, 12);

        System.out.println("Index: " + index);
    }
}
```

**Временска сложеност**

| Случај   | Временска сложеност |
|----------|--------------------:|
| Најдобар |                O(1) |
| Просечен |                O(n) |
| Најлош   |                O(n) |

Најдобриот случај се јавува кога бараниот елемент е првиот во колекцијата, па е потребна само една споредба. Најлошиот
случај се јавува кога елементот е последен или воопшто не постои, па мора да се проверат сите `n` елементи.

**Просторна сложеност**

Просторната сложеност е **O (1)**, бидејќи алгоритмот користи само константен дополнителен простор, независно од бројот
на елементи во колекцијата.

### Бинарно пребарување (Binary Search)

**Основна идеја**

Бинарното пребарување ја дели колекцијата на половини и во секој чекор ја отфрла половината во која не може да се наоѓа
бараниот елемент.

**Предуслов:** Колекцијата мора да биде сортирана според клучното поле, во растечки или опаѓачки редослед. Во следниот
пример се користи растечки редослед.

Бинарното пребарување е особено погодно за големи сортирани колекции, бидејќи не мора да го проверува секој елемент
поединечно.

**Постапка**

1. Се поставуваат границите на пребарувањето: почетен и краен индекс.
2. Се пресметува средишниот индекс.
3. Се споредува средишниот елемент со бараниот клуч.
4. Ако се еднакви, пребарувањето завршува.
5. Ако бараниот клуч е помал, пребарувањето продолжува во левата половина.
6. Ако е поголем, пребарувањето продолжува во десната половина.
7. Постапката се повторува додека елементот не се пронајде или интервалот не стане празен.

**Псевдокод**

```text
BINARY_SEARCH(A, n, key)
    left = 0
    right = n - 1

    while left <= right
        mid = left + (right - left) / 2

        if A[mid] == key
            return mid

        if A[mid] < key
            left = mid + 1
        else
            right = mid - 1

    return -1
```

**Пример**

За сортираната низа:

```text
A = [2, 5, 8, 12, 16, 23, 38]
key = 16
```

Пребарувањето се одвива во следните чекори:

**Чекор 1:** Се проверува средишниот елемент на низата.

```text
[2, 5, 8, 12, 16, 23, 38]
             ↑
          mid = 3
          A[3] = 12

16 > 12 → продолжува во десната половина
```

**Чекор 2:** Се пребарува во десната половина.

```text
[16, 23, 38]
      ↑
   mid = 5
   A[5] = 23

16 < 23 → продолжува во левата половина
```

**Чекор 3:** Се проверува преостанатиот елемент.

```text
[16]
  ↑
mid = 4
A[4] = 16

16 == 16 → пронајден на индекс 4
```

**Java имплементација**

```java
public class BinarySearch {

    static int search(int[] array, int key) {
        int left = 0;
        int right = array.length - 1;

        while (left <= right) {
            int mid = left + (right - left) / 2;

            if (array[mid] == key) {
                return mid;
            }

            if (array[mid] < key) {
                left = mid + 1;
            } else {
                right = mid - 1;
            }
        }

        return -1;
    }

    static void main(String[] args) {
        int[] array = {2, 5, 8, 12, 16, 23, 38};

        int index = search(array, 16);

        System.out.println("Index: " + index);
    }
}
```

**Временска сложеност**

| Случај   | Временска сложеност |
|----------|--------------------:|
| Најдобар |                O(1) |
| Просечен |            O(log n) |
| Најлош   |            O(log n) |

Најдобриот случај се јавува кога бараниот елемент е на средишната позиција и се пронаоѓа со една споредба. Во просечниот
и најлошиот случај, интервалот на пребарување се преполовува во секој чекор, па бројот на потребни споредби расте
логаритамски.

**Просторна сложеност**

Просторната сложеност е **O (1)** за итеративната имплементација, бидејќи се користат само неколку дополнителни
променливи (`left`, `right` и `mid`).

Бинарното пребарување е значително поефикасно од секвенцијалното за големи сортирани колекции. Пред неговата примена,
колекцијата мора да биде сортирана според клучното поле.

### Споредба на алгоритмите за пребарување

| Карактеристика                 | Секвенцијално пребарување |         Бинарно пребарување |
|--------------------------------|--------------------------:|----------------------------:|
| Потребна е сортирана колекција |                        Не |                          Да |
| Најдобра временска сложеност   |                      O(1) |                        O(1) |
| Просечна временска сложеност   |                      O(n) |                    O(log n) |
| Најлоша временска сложеност    |                      O(n) |                    O(log n) |
| Просторна сложеност            |                      O(1) |                        O(1) |
| Начин на пребарување           |        Елемент по елемент | Преполовување на интервалот |

## Споредување на колекции (Comparing Collections)

Во оваа целина се обработува проверката дали две колекции ги содржат истите елементи. Се разгледуваат пристапите за
несортирани колекции, сортирани колекции и колекции што прво треба да се сортираат.

Во примерите се претпоставува дека редоследот на елементите не е важен, но бројот на појавувања на секој елемент е
важен. На пример, `[1, 2, 2]` и `[1, 1, 2]` не се еднакви бидејќи бројот на појавувања на вредностите е различен.

### Споредување на несортирани колекции

**Основна идеја**

За секој елемент од првата колекција се бара еднаков елемент во втората колекција. Секој пронајден елемент се означува
како искористен за да не може повторно да се искористи при споредување на дупликати.

**Постапка**

1. Се проверува дали колекциите имаат еднаков број елементи.
2. За секој елемент од првата колекција се пребарува соодветен елемент во втората.
3. Пронајдениот елемент се означува како искористен.
4. Ако за некој елемент не постои соодветен елемент, колекциите не се еднакви.
5. Ако сите елементи се совпаѓаат, колекциите се еднакви.

**Псевдокод**

```text
COMPARE_UNSORTED(A, B)
    if length(A) != length(B)
        return false

    used = array of false values

    for each element x in A
        found = false

        for j = 0 to length(B) - 1
            if B[j] == x AND used[j] == false
                used[j] = true
                found = true
                break

        if found == false
            return false

    return true
```

**Пример**

```text
A = [3, 1, 2, 3]
B = [2, 3, 3, 1]
```

Секој елемент од A има соодветен неискористен елемент во B. Затоа колекциите се еднакви.

**Java имплементација**

```java
public class CompareUnsorted {

    static boolean areEqual(int[] first, int[] second) {
        if (first.length != second.length) {
            return false;
        }

        boolean[] used = new boolean[second.length];

        for (int value : first) {
            boolean found = false;

            for (int j = 0; j < second.length; j++) {
                if (!used[j] && second[j] == value) {
                    used[j] = true;
                    found = true;
                    break;
                }
            }

            if (!found) {
                return false;
            }
        }

        return true;
    }

    static void main(String[] args) {
        int[] first = {3, 1, 2, 3};
        int[] second = {2, 3, 3, 1};

        System.out.println(areEqual(first, second));
    }
}
```

**Сложеност**

- Временска сложеност: **O (n²)**.
- Просторна сложеност: **O (n)** поради помошната низа `used`.

### Споредување на сортирани колекции

**Основна идеја**

Ако двете колекции се сортирани, нивните елементи може да се споредуваат на исти позиции. Ако сите соодветни елементи се
еднакви, колекциите се еднакви.

**Постапка**

1. Се проверува дали колекциите имаат еднаков број елементи.
2. Се започнува од првата позиција.
3. Се споредуваат елементите на истите позиции.
4. Ако се пронајде разлика, колекциите не се еднакви.
5. Ако сите елементи се еднакви, колекциите се еднакви.

**Псевдокод**

```text
COMPARE_SORTED(A, B)
    if length(A) != length(B)
        return false

    for i = 0 to length(A) - 1
        if A[i] != B[i]
            return false

    return true
```

**Пример**

```text
A = [1, 2, 3, 3]
B = [1, 2, 3, 3]

Резултат: колекциите се еднакви.
```

**Java имплементација**

```java
public class CompareSorted {

    static boolean areEqual(int[] first, int[] second) {
        if (first.length != second.length) {
            return false;
        }

        for (int i = 0; i < first.length; i++) {
            if (first[i] != second[i]) {
                return false;
            }
        }

        return true;
    }

    static void main(String[] args) {
        int[] first = {1, 2, 3, 3};
        int[] second = {1, 2, 3, 3};

        System.out.println(areEqual(first, second));
    }
}
```

**Сложеност**

- Временска сложеност: **O (n)**.
- Просторна сложеност: **O (1)**.

### Споредување по претходно сортирање

**Основна идеја**

Кога колекциите се несортирани, може прво да се сортираат, а потоа да се споредуваат на исти позиции.

**Постапка**

1. Се проверува дали колекциите имаат еднаков број елементи.
2. Двете колекции се копираат и сортираат.
3. Сортираните колекции се споредуваат елемент по елемент.
4. Ако сите елементи се еднакви, колекциите се еднакви.

**Псевдокод**

```text
COMPARE_AFTER_SORTING(A, B)
    if length(A) != length(B)
        return false

    SORT(A)
    SORT(B)

    return COMPARE_SORTED(A, B)
```

**Пример**

```text
A = [3, 1, 2]
B = [2, 3, 1]

По сортирањето:

A = [1, 2, 3]
B = [1, 2, 3]

Резултат: колекциите се еднакви.
```

**Java имплементација**

```java
import java.util.Arrays;

public class CompareAfterSorting {

    static boolean areEqual(int[] first, int[] second) {
        if (first.length != second.length) {
            return false;
        }

        int[] sortedFirst = first.clone();
        int[] sortedSecond = second.clone();

        Arrays.sort(sortedFirst);
        Arrays.sort(sortedSecond);

        return Arrays.equals(sortedFirst, sortedSecond);
    }

    static void main(String[] args) {
        int[] first = {3, 1, 2};
        int[] second = {2, 3, 1};

        System.out.println(areEqual(first, second));
    }
}
```

**Сложеност**

- Временска сложеност: **O (n log n)** за сортирање на двете колекции и O (n) за споредување.
- Просторна сложеност: **O (n)** за двете копии, плус дополнителниот простор што го користи `Arrays.sort`.

## Сортирање (Sorting)

Сортирањето е процес на подредување на елементите во колекција според одреден клуч. Во оваа целина се обработуваат
алгоритмите за сортирање со споредување и без споредување, како и разликата меѓу внатрешно и надворешно сортирање.

### Основни поими и класификација на сортирањето

**Сортирање (Sorting)** е процес на подредување на елементите во колекција во растечки или опаѓачки редослед според
одреден клуч.

Резултатот од сортирањето е пермутација на оригиналната колекција. Тоа значи дека сите оригинални елементи остануваат
присутни, но нивниот редослед се менува.

Сортирањето се класифицира според два независни критериуми.

**Според местото каде што се обработуваат податоците:**

- **Внатрешно сортирање (Internal Sorting)** – сите податоци што се сортираат можат да се сместат во главната меморија
  (RAM).
- **Надворешно сортирање (External Sorting)** – податоците се поголеми од достапната главна меморија и мора да се
  обработуваат во делови со користење секундарна меморија, како диск.

**Според начинот на одредување на редоследот:**

- **Сортирање со споредување (Comparison-Based Sorting)** – редоследот се одредува преку споредба на парови елементи.
- **Сортирање без споредување (Non-Comparison-Based Sorting)** – редоследот се одредува со користење на својствата на
  клучевите, како нивната вредност или цифрите.

Овие поделби не се меѓусебно исклучиви. На пример, Quick Sort е внатрешен алгоритам со споредување, додека Counting Sort
е внатрешен алгоритам без споредување.

### Основни карактеристики на алгоритмите

**Стабилност (Stability)**

Алгоритамот е стабилен ако елементите со еднакви клучеви го задржуваат својот релативен редослед од оригиналната
колекција.

**Сортирање на самото место (In-place Sorting)**

Алгоритамот се смета за in-place ако сортира директно во оригиналната колекција, без потреба од дополнителна колекција
со големина пропорционална на бројот на елементи. Вообичаено се смета дека користи O (1) дополнителен простор. Кај
рекурзивните алгоритми треба да се земе предвид и просторот за рекурзивниот стек.

**Подели и владеј (Divide and Conquer)**

Ова е техника при која проблемот се дели на помали подпроблеми, тие се решаваат одделно, а нивните резултати се
комбинираат. Quick Sort и Merge Sort ја користат оваа техника.

### Сортирање со споредување (Comparison-Based Sorting)

Кај овие алгоритми, два елемента се споредуваат за да се одреди нивниот меѓусебен редослед. Нивната теоретска долна
граница за најлош случај е Ω (n log n).

#### Сортирање со избор (Selection Sort)

**Основна идеја**

Selection Sort во секоја итерација го пронаоѓа најмалиот елемент од несортираниот дел и го поставува на неговата конечна
позиција.

**Постапка**

1. Се започнува од првата позиција.
2. Се пронаоѓа најмалиот елемент во преостанатиот несортиран дел.
3. Најмалиот елемент се заменува со елементот на тековната позиција.
4. Се продолжува со следната позиција.
5. Постапката завршува кога ќе се сортираат сите позиции освен последната.

**Псевдокод**

```text
SELECTION_SORT(A, n)
    for i = 0 to n - 2
        minIndex = i

        for j = i + 1 to n - 1
            if A[j] < A[minIndex]
                minIndex = j

        swap A[i] and A[minIndex]
```

**Пример**

```text
Почетна низа:
[64, 25, 12, 22, 11]

Итерација 1:
[11, 25, 12, 22, 64]

Итерација 2:
[11, 12, 25, 22, 64]

Итерација 3:
[11, 12, 22, 25, 64]

Итерација 4:
[11, 12, 22, 25, 64]
```

**Java имплементација**

```java
import java.util.Arrays;

public class SelectionSort {

    static void sort(int[] array) {
        for (int i = 0; i < array.length - 1; i++) {
            int minIndex = i;

            for (int j = i + 1; j < array.length; j++) {
                if (array[j] < array[minIndex]) {
                    minIndex = j;
                }
            }

            int temp = array[i];
            array[i] = array[minIndex];
            array[minIndex] = temp;
        }
    }

    static void main(String[] args) {
        int[] array = {64, 25, 12, 22, 11};

        sort(array);

        System.out.println(Arrays.toString(array));
    }
}
```

|------------------------------|------------------------------------|

| Просечна временска сложеност | O(n²)                              |
| Најлоша временска сложеност  | O(n²)                              |

#### Меуресто сортирање (Bubble Sort)

**Основна идеја**

Bubble Sort ги споредува соседните елементи и ги заменува ако не се во правилен редослед. По секоја итерација,
најголемиот елемент од несортираниот дел се преместува на неговата конечна позиција.

**Постапка**

1. Се споредуваат првиот и вториот елемент.
2. Ако левиот елемент е поголем, елементите се заменуваат.
3. Се продолжува со следните соседни елементи.
4. По завршување на итерацијата, најголемиот елемент е на крајот.
5. Постапката се повторува за преостанатиот несортиран дел.
6. Ако во една итерација нема замени, алгоритмот завршува.

**Псевдокод**

```text
BUBBLE_SORT(A, n)
    for i = 0 to n - 2
        swapped = false

        for j = 0 to n - 2 - i
            if A[j] > A[j + 1]
                swap A[j] and A[j + 1]
                swapped = true

        if swapped == false
            break
```

**Пример**

```text
Почетна низа:
[5, 1, 4, 2, 8]

Итерација 1:
[1, 4, 2, 5, 8]

Итерација 2:
[1, 2, 4, 5, 8]

Итерација 3:
[1, 2, 4, 5, 8]
```

**Java имплементација**

```java
import java.util.Arrays;

public class BubbleSort {

    static void sort(int[] array) {
        for (int i = 0; i < array.length - 1; i++) {
            boolean swapped = false;

            for (int j = 0; j < array.length - 1 - i; j++) {
                if (array[j] > array[j + 1]) {
                    int temp = array[j];
                    array[j] = array[j + 1];
                    array[j + 1] = temp;

                    swapped = true;
                }
            }

            if (!swapped) {
                break;
            }
        }
    }

    static void main(String[] args) {
        int[] array = {5, 1, 4, 2, 8};

        sort(array);

        System.out.println(Arrays.toString(array));
    }
}
```

| Карактеристика               | Вредност |
|------------------------------|----------|
| Најдобра временска сложеност | O(n)     |
| Просечна временска сложеност | O(n²)    |
| Најлоша временска сложеност  | O(n²)    |
| Просторна сложеност          | O(1)     |
| Стабилен                     | Да       |
| In-place                     | Да       |

Најдобрата сложеност O (n) се постигнува кога низата е веќе сортирана и алгоритмот користи проверка дали имало замени.

#### Сортирање со вметнување (Insertion Sort)

**Основна идеја**

Insertion Sort ја гради сортираната низа постепено. Секој нов елемент се вметнува на соодветната позиција во веќе
сортираниот дел.

**Постапка**

1. Првиот елемент се смета за сортиран.
2. Се зема следниот елемент како тековен елемент.
3. Се споредува со елементите од сортираниот дел, почнувајќи од десно кон лево.
4. Поголемите елементи се поместуваат една позиција надесно.
5. Тековниот елемент се вметнува на ослободената позиција.
6. Постапката се повторува за сите преостанати елементи.

**Псевдокод**

```text
INSERTION_SORT(A, n)
    for i = 1 to n - 1
        current = A[i]
        j = i - 1

        while j >= 0 AND A[j] > current
            A[j + 1] = A[j]
            j = j - 1

        A[j + 1] = current
```

**Пример**

```text
Почетна низа:
[5, 2, 4, 6, 1]

Вметнување на 2:
[2, 5, 4, 6, 1]

Вметнување на 4:
[2, 4, 5, 6, 1]

Вметнување на 6:
[2, 4, 5, 6, 1]

Вметнување на 1:
[1, 2, 4, 5, 6]
```

**Java имплементација**

```java
import java.util.Arrays;

public class InsertionSort {

    static void sort(int[] array) {
        for (int i = 1; i < array.length; i++) {
            int current = array[i];
            int j = i - 1;

            while (j >= 0 && array[j] > current) {
                array[j + 1] = array[j];
                j--;
            }

            array[j + 1] = current;
        }
    }

    static void main(String[] args) {
        int[] array = {5, 2, 4, 6, 1};

        sort(array);

        System.out.println(Arrays.toString(array));
    }
}
```

**Сложеност и карактеристики**

| Карактеристика               | Вредност |
|------------------------------|----------|
| Најдобра временска сложеност | O(n)     |
| Просечна временска сложеност | O(n²)    |
| Најлоша временска сложеност  | O(n²)    |
| Просторна сложеност          | O(1)     |
| Стабилен                     | Да       |
| In-place                     | Да       |

Insertion Sort е особено ефикасен за мали или речиси сортирани низи.

#### Брзо сортирање (Quick Sort)

**Основна идеја**

Quick Sort користи техника подели и владеј (Divide and Conquer). Низата се дели околу избран елемент наречен pivot
(пивот). По поделбата, елементите помали или еднакви на пивотот се поставуваат лево, а поголемите десно. Потоа двата
дела се сортираат рекурзивно.

**Постапка**

1. Се избира пивот.
2. Се врши поделба на низата околу пивотот.
3. Пивотот се поставува на неговата конечна позиција.
4. Рекурзивно се сортира левиот дел.
5. Рекурзивно се сортира десниот дел.
6. Постапката завршува кога поднизите имаат најмногу еден елемент.

**Псевдокод**

```text
QUICK_SORT(A, low, high)
    if low < high
        pivotIndex = PARTITION(A, low, high)

        QUICK_SORT(A, low, pivotIndex - 1)
        QUICK_SORT(A, pivotIndex + 1, high)


PARTITION(A, low, high)
    pivot = A[high]
    i = low - 1

    for j = low to high - 1
        if A[j] <= pivot
            i = i + 1
            swap A[i] and A[j]

    swap A[i + 1] and A[high]

    return i + 1
```

**Пример**

```text
Почетна низа:
[8, 3, 1, 7, 0, 10, 2]

Пивот = 2

По поделбата:
[1, 0, 2, 7, 8, 10, 3]

Потоа рекурзивно се сортираат левата и десната подниза.

Резултат:
[0, 1, 2, 3, 7, 8, 10]
```

По поделбата, левата и десната подниза сè уште не се сортирани. Гарантирано е само дека елементите лево од пивотот се
помали или еднакви на него, а елементите десно се поголеми.

**Java имплементација**

```java
import java.util.Arrays;

public class QuickSort {

    static void sort(int[] array, int low, int high) {
        if (low >= high) {
            return;
        }

        int pivotIndex = partition(array, low, high);

        sort(array, low, pivotIndex - 1);
        sort(array, pivotIndex + 1, high);
    }

    static int partition(int[] array, int low, int high) {
        int pivot = array[high];
        int i = low - 1;

        for (int j = low; j < high; j++) {
            if (array[j] <= pivot) {
                i++;

                int temp = array[i];
                array[i] = array[j];
                array[j] = temp;
            }
        }

        int temp = array[i + 1];
        array[i + 1] = array[high];
        array[high] = temp;

        return i + 1;
    }

    static void main(String[] args) {
        int[] array = {8, 3, 1, 7, 0, 10, 2};

        sort(array, 0, array.length - 1);

        System.out.println(Arrays.toString(array));
    }
}
```

**Сложеност и карактеристики**

| Карактеристика               | Вредност                                      |
|------------------------------|-----------------------------------------------|
| Најдобра временска сложеност | O(n log n)                                    |
| Просечна временска сложеност | O(n log n)                                    |
| Најлоша временска сложеност  | O(n²)                                         |
| Просечна просторна сложеност | O(log n)                                      |
| Најлоша просторна сложеност  | O(n)                                          |
| Стабилен                     | Не                                            |
| In-place                     | Да, не користи дополнителна низа за сортирање |

Во оваа имплементација пивотот секогаш е последниот елемент. Ако низата е веќе сортирана или обратно сортирана, може да
се добијат нерамномерни поделби и временска сложеност O (n²). Просторот за рекурзивниот стек е вклучен во просторната
сложеност.

#### Сортирање со спојување (Merge Sort)

**Основна идеја**

Merge Sort ја дели низата на две половини, ги сортира рекурзивно и потоа ги спојува во една сортирана низа.

**Постапка**

1. Низата се дели на две приближно еднакви половини.
2. Секоја половина се сортира рекурзивно.
3. Двете сортирани половини се спојуваат.
4. Постапката завршува кога ќе се добие целосно сортирана низа.

**Псевдокод**

```text
MERGE_SORT(A, left, right)
    if left < right
        mid = left + (right - left) / 2

        MERGE_SORT(A, left, mid)
        MERGE_SORT(A, mid + 1, right)

        MERGE(A, left, mid, right)


MERGE(A, left, mid, right)
    create temporary array T

    i = left
    j = mid + 1

    while i <= mid AND j <= right
        if A[i] <= A[j]
            copy A[i] into T
            i = i + 1
        else
            copy A[j] into T
            j = j + 1

    copy remaining elements from left half
    copy remaining elements from right half

    copy T into A[left...right]
```

**Пример**

```text
Почетна низа:
[8, 3, 2, 9]

Поделба:
[8, 3]    [2, 9]

Повторна поделба:
[8] [3]   [2] [9]

Спојување:
[3, 8]    [2, 9]

Конечно спојување:
[2, 3, 8, 9]
```

**Java имплементација**

```java
import java.util.Arrays;

public class MergeSort {

    static void sort(int[] array) {
        if (array.length < 2) {
            return;
        }

        int[] temp = new int[array.length];

        sort(array, temp, 0, array.length - 1);
    }

    static void sort(int[] array, int[] temp, int left, int right) {
        if (left >= right) {
            return;
        }

        int mid = left + (right - left) / 2;

        sort(array, temp, left, mid);
        sort(array, temp, mid + 1, right);

        merge(array, temp, left, mid, right);
    }

    static void merge(
            int[] array,
            int[] temp,
            int left,
            int mid,
            int right
    ) {
        int i = left;
        int j = mid + 1;
        int k = left;

        while (i <= mid && j <= right) {
            if (array[i] <= array[j]) {
                temp[k++] = array[i++];
            } else {
                temp[k++] = array[j++];
            }
        }

        while (i <= mid) {
            temp[k++] = array[i++];
        }

        while (j <= right) {
            temp[k++] = array[j++];
        }

        System.arraycopy(temp, left, array, left, right - left + 1);
    }

    static void main(String[] args) {
        int[] array = {8, 3, 2, 9, 7, 1, 5, 4};

        sort(array);

        System.out.println(Arrays.toString(array));
    }
}
```

**Сложеност и карактеристики**

| Карактеристика               | Вредност   |
|------------------------------|------------|
| Најдобра временска сложеност | O(n log n) |
| Просечна временска сложеност | O(n log n) |
| Најлоша временска сложеност  | O(n log n) |
| Просторна сложеност          | O(n)       |
| Стабилен                     | Да         |
| In-place                     | Не         |

Merge Sort има предвидлива временска сложеност O (n log n), но бара дополнителна меморија за спојување на поднизите.

### Сортирање без споредување (Non-Comparison-Based Sorting)

Кај овие алгоритми, редоследот не се одредува преку директна споредба на парови елементи. Наместо тоа, се користат
својствата на клучевите, како нивната вредност или цифрите.

#### Сортирање со броење (Counting Sort)

**Основна идеја**

Counting Sort ги брои појавувањата на секоја вредност во низата. Потоа ги користи тие броеви за да ги постави елементите
на соодветните позиции во сортираниот резултат.

Алгоритмот е погоден за цели броеви кога опсегот на вредности не е многу поголем од бројот на елементи.

**Постапка**

1. Се одредуваат најмалата и најголемата вредност.
2. Се создава помошна низа за броење на вредностите.
3. Се брои колку пати се појавува секоја вредност.
4. Броевите се претвораат во кумулативни позиции.
5. Елементите се поставуваат во излезната низа.
6. Излезната низа се копира назад во оригиналната.

**Псевдокод**

```text
COUNTING_SORT(A, n)
    find minimum and maximum values

    create count array C
    create output array B

    for each value x in A
        C[x - minimum]++

    for i = 1 to length(C) - 1
        C[i] = C[i] + C[i - 1]

    for i = n - 1 down to 0
        B[C[A[i] - minimum] - 1] = A[i]
        C[A[i] - minimum]--

    copy B into A
```

**Пример**

```text
Почетна низа:
[4, 2, 2, 8, 3, 3, 1]

Броење:
1 → 1 појавување
2 → 2 појавувања
3 → 2 појавувања
4 → 1 појавување
8 → 1 појавување

Резултат:
[1, 2, 2, 3, 3, 4, 8]
```

**Java имплементација**

```java
import java.util.Arrays;

public class CountingSort {

    static void sort(int[] array) {
        if (array.length < 2) {
            return;
        }

        int min = array[0];
        int max = array[0];

        for (int value : array) {
            min = Math.min(min, value);
            max = Math.max(max, value);
        }

        long range = (long) max - min + 1;

        if (range > Integer.MAX_VALUE) {
            throw new IllegalArgumentException(
                    "The value range is too large."
            );
        }

        int[] count = new int[(int) range];
        int[] output = new int[array.length];

        for (int value : array) {
            int index = (int) ((long) value - min);
            count[index]++;
        }

        for (int i = 1; i < count.length; i++) {
            count[i] += count[i - 1];
        }

        for (int i = array.length - 1; i >= 0; i--) {
            int value = array[i];
            int index = (int) ((long) value - min);
            int position = count[index] - 1;

            output[position] = value;
            count[index]--;
        }

        System.arraycopy(output, 0, array, 0, array.length);
    }

    static void main(String[] args) {
        int[] array = {4, 2, 2, 8, 3, 3, 1};

        sort(array);

        System.out.println(Arrays.toString(array));
    }
}
```

**Сложеност и карактеристики**

Нека `n` е бројот на елементи, а `k` е опсегот на вредности.

| Карактеристика      | Вредност |
|---------------------|----------|
| Временска сложеност | O(n + k) |
| Просторна сложеност | O(n + k) |
| Стабилен            | Да       |
| In-place            | Не       |

Оваа имплементација поддржува негативни и позитивни цели броеви, но бара опсегот на вредности да биде доволно мал за да
може да се смести во меморија.

#### Сортирање со кофи (Bucket Sort)

**Основна идеја**

Bucket Sort ги распределува елементите во повеќе кофи според нивната вредност. Секоја кофа се сортира одделно, а потоа
кофите се спојуваат по редослед.

Во примерот се користат децимални броеви во интервалот [0, 1).

**Постапка**

1. Се создаваат n празни кофи.
2. Секој елемент се распределува во соодветна кофа.
3. Секоја кофа се сортира одделно.
4. Елементите од кофите се собираат по редослед.

**Псевдокод**

```text
BUCKET_SORT(A, n)
    create n empty buckets

    for each value x in A
        index = floor(n * x)
        insert x into bucket[index]

    for each bucket
        sort bucket

    concatenate all buckets in order
```

**Пример**

```text
Почетна низа:
[0.42, 0.32, 0.23, 0.52, 0.25]

Bucket 0: [0.23, 0.25]
Bucket 1: [0.32]
Bucket 2: [0.42]
Bucket 3: [0.52]

Резултат:
[0.23, 0.25, 0.32, 0.42, 0.52]
```

**Java имплементација**

```java
import java.util.ArrayList;
import java.util.Arrays;
import java.util.List;

public class BucketSort {

    static void sort(double[] array) {
        int n = array.length;

        if (n < 2) {
            return;
        }

        List<List<Double>> buckets = new ArrayList<>();

        for (int i = 0; i < n; i++) {
            buckets.add(new ArrayList<>());
        }

        for (double value : array) {
            if (!Double.isFinite(value) || value < 0.0 || value >= 1.0) {
                throw new IllegalArgumentException(
                        "Values must be finite and in [0, 1)."
                );
            }

            int index = (int) (n * value);
            buckets.get(index).add(value);
        }

        for (List<Double> bucket : buckets) {
            insertionSort(bucket);
        }

        int index = 0;

        for (List<Double> bucket : buckets) {
            for (double value : bucket) {
                array[index++] = value;
            }
        }
    }

    static void insertionSort(List<Double> bucket) {
        for (int i = 1; i < bucket.size(); i++) {
            double current = bucket.get(i);
            int j = i - 1;

            while (j >= 0 && bucket.get(j) > current) {
                bucket.set(j + 1, bucket.get(j));
                j--;
            }

            bucket.set(j + 1, current);
        }
    }

    static void main(String[] args) {
        double[] array = {0.42, 0.32, 0.23, 0.52, 0.25};

        sort(array);

        System.out.println(Arrays.toString(array));
    }
}
```

**Сложеност и карактеристики**

Нека `n` е бројот на елементи, а `k` е бројот на кофи.

| Карактеристика               | Вредност                                          |
|------------------------------|---------------------------------------------------|
| Просечна временска сложеност | O(n + k), при рамномерна распределба              |
| Најлоша временска сложеност  | O(n²), кога сите елементи завршуваат во една кофа |
| Просторна сложеност          | O(n + k)                                          |
| Стабилен                     | Да, со стабилно сортирање во кофите               |
| In-place                     | Не                                                |

Во оваа имплементација бројот на кофи е `k = n`, па просечната временска сложеност е O (n), при рамномерна распределба,
а просторната сложеност е O (n). Овој пример е наменет за вредности во интервалот [0, 1). За други опсези е потребно
соодветно пресметување на индексот на кофата.

#### Радикс сортирање (Radix Sort)

**Основна идеја**

Radix Sort ги сортира целите броеви според нивните цифри, една по една. Кај LSD Radix Sort (Least Significant Digit),
сортирањето започнува од најмалку значајната цифра и продолжува кон најзначајната.

За секоја позиција се користи стабилен алгоритам за сортирање, најчесто Counting Sort.

**Постапка**

1. Се одредува најголемиот број цифри кај елементите.
2. Се започнува од цифрата на единиците.
3. Се сортираат елементите според тековната цифра со стабилен Counting Sort.
4. Се продолжува со десетките, стотките итн.
5. Постапката завршува кога ќе се обработат сите цифри.

**Псевдокод**

```text
RADIX_SORT(A, n)
    find maximum value

    exp = 1

    while maximum / exp > 0
        STABLE_COUNTING_SORT_BY_DIGIT(A, exp)
        exp = exp * 10
```

**Пример**

```text
Почетна низа:
[170, 45, 75, 90, 802, 24, 2, 66]

По сортирање според единици:
[170, 90, 802, 2, 24, 45, 75, 66]

По сортирање според десетки:
[802, 2, 24, 45, 66, 170, 75, 90]

По сортирање според стотки:
[2, 24, 45, 66, 75, 90, 170, 802]
```

**Java имплементација**

```java
import java.util.Arrays;

public class RadixSort {

    static void sort(int[] array) {
        if (array.length < 2) {
            return;
        }

        int max = array[0];

        for (int value : array) {
            if (value < 0) {
                throw new IllegalArgumentException(
                        "Only non-negative integers are supported."
                );
            }

            max = Math.max(max, value);
        }

        int[] output = new int[array.length];

        for (long exp = 1; max / exp > 0; exp *= 10) {
            countingSortByDigit(array, output, exp);
        }
    }

    static void countingSortByDigit(
            int[] array,
            int[] output,
            long exp
    ) {
        int[] count = new int[10];

        for (int value : array) {
            int digit = (int) ((value / exp) % 10);
            count[digit]++;
        }

        for (int i = 1; i < count.length; i++) {
            count[i] += count[i - 1];
        }

        for (int i = array.length - 1; i >= 0; i--) {
            int digit = (int) ((array[i] / exp) % 10);
            output[--count[digit]] = array[i];
        }

        System.arraycopy(output, 0, array, 0, array.length);
    }

    static void main(String[] args) {
        int[] array = {170, 45, 75, 90, 802, 24, 2, 66};

        sort(array);

        System.out.println(Arrays.toString(array));
    }
}
```

**Сложеност и карактеристики**

Нека `n` е бројот на елементи, `d` е бројот на цифри во најголемиот број, а `b` е основата на броевниот систем. Во
примерот основата е 10.

| Карактеристика      | Вредност    |
|---------------------|-------------|
| Временска сложеност | O(d(n + b)) |
| Просторна сложеност | O(n + b)    |
| Стабилен            | Да          |
| In-place            | Не          |

Оваа имплементација поддржува ненегативни цели броеви. Негативните броеви бараат дополнителна обработка.

### Внатрешно и надворешно сортирање (Internal and External Sorting)

Оваа поделба се однесува на местото каде што се обработуваат податоците, а не на начинот на споредување.

**Внатрешно сортирање**

Внатрешно сортирање се користи кога целата колекција може да се смести во главната меморија. Selection Sort, Bubble
Sort, Insertion Sort, Quick Sort, Merge Sort, Counting Sort, Bucket Sort и Radix Sort можат да се користат како
внатрешни алгоритми.

**Надворешно сортирање**

Надворешно сортирање се користи кога колекцијата е преголема за да се смести целосно во главната меморија. Податоците се
обработуваат во делови, а резултатите се запишуваат и читаат од секундарна меморија.

Типична постапка е:

1. Големата датотека се дели на помали делови што можат да се сместат во RAM.
2. Секој дел се вчитува и се сортира одделно.
3. Сортираните делови се запишуваат како привремени датотеки.
4. Привремените сортирани датотеки се спојуваат во една конечна сортирана датотека.

**Пример**

Ако датотека содржи 100 милиони записи, а меморијата може да обработи само 1 милион записи одеднаш, датотеката може да
се подели на 100 делови. Секој дел се сортира одделно, а потоа сортираните делови се спојуваат.

Надворешното сортирање често користи External Merge Sort, односно надворешно сортирање со спојување. Тоа е примена на
принципот на Merge Sort при која се минимизира бројот на читања и запишувања на диск.

### Теоретска долна граница на сортирањето со споредување

Кај алгоритмите за сортирање со споредување, редоследот се одредува преку споредување на парови елементи.

За `n` различни елементи постојат `n!` можни пермутации. Алгоритмот мора да може да ги разликува сите тие можни
редоследи.

Ова може да се претстави со дрво на одлуки (Decision Tree). Секој внатрешен јазол претставува споредба, а секој лист
претставува можен конечен редослед.

Бидејќи дрвото мора да има најмалку `n!` листови, неговата висина `h` мора да ја задоволува нееднаквоста:

```text
2^h >= n!
```

Со логаритмирање:

```text
h >= log2(n!)
```

Од ова произлегува долната граница:

```text
Ω(n log n)
```

Затоа ниту еден алгоритам за сортирање што користи само споредување не може да има временска сложеност подобра од Ω (n
log n) во најлош случај.

Counting Sort, Bucket Sort и Radix Sort не ја нарушуваат оваа граница бидејќи не се засноваат исклучиво на споредување
на парови елементи. Тие користат дополнителни претпоставки за вредностите и претставувањето на клучевите.

## Најважно за паметење

- Секвенцијалното пребарување ги проверува елементите еден по еден и работи и со сортирани и со несортирани колекции.
- Бинарното пребарување бара сортирана колекција и во секој чекор го преполовува интервалот на пребарување.
- Несортираните колекции може да се споредуваат со повторено пребарување, што може да бара O (n²) време.
- Сортираните колекции може да се споредуваат позиција по позиција за O (n) време.
- Сортирањето со споредување го одредува редоследот преку споредба на парови елементи.
- Сортирањето без споредување ги користи својствата на клучевите.
- Внатрешното и надворешното сортирање се разликуваат според местото на обработка на податоците.
- Selection Sort, Bubble Sort и Insertion Sort имаат најлоша временска сложеност O (n²).
- Quick Sort има просечна временска сложеност O (n log n), но најлоша O (n²).
- Merge Sort има временска сложеност O (n log n) во сите случаи и бара O (n) дополнителен простор.
- Counting Sort има сложеност O (n + k), каде што `k` е опсегот на вредности.
- Bucket Sort е ефикасен кога вредностите се рамномерно распределени.
- Radix Sort ги обработува цифрите на броевите една по една.
- Алгоритмите за сортирање со споредување имаат долна граница Ω (n log n) во најлош случај.
